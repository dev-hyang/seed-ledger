# 稻种账本 · Rice Seed Ledger

稻种经销商用的进货、库存、销售、赊账、对账、报表工具。手机和电脑网页都能用，可离线录入，多人（朋友 + 合伙人）云端同步。
只提供交易记录和风险提示，不构成法律意见。设计与口径见 [docs/design.md](docs/design.md)。

## 现在能做什么
- **进货 / 退货 / 库存**：早稻、一晚、二晚（名称可改、可新增）；品种按年设进货价和预售价；退货给种子公司。
- **种子公司钱池**：打款进池，进货和手续费从池里扣，退货抵扣回池；余额结转明年，拖欠要补款；退货比例高时按规则建议手续费。
- **三种售卖方式**共用一个模型：当场结清 / 付定金 / 全部赊账；可加送货成本（人工 + 车费）。
- **价格**：单据价 + 仅自己可见的「私下价」；讨账时记议价、折上折、坏账核销（带原因，可撤销、留痕）。AI 议价建议可选。
- **扫描 / 导入销售**：拍单据、选相册照片 / PDF / Excel / CSV、或粘贴文字，AI 读成销售草稿 → 逐笔核对（客户、品种、数量、单价、收款都能改）→ 才入库。认出已有客户和品种，单位自动换成斤，疑似重复的默认不勾。手抄本的一页上有几位客户就读成几笔，可用来迁移历史数据。入口在「销售」页和概览页的「📷 扫描 / 导入」。发给 AI 前要先勾选同意；邮箱和长数字串（身份证、银行卡）会先抹掉；不保存原图。
- **版本号**：顶栏、概览页底部、设置、更多页都显示，发布新版后对一下就知道有没有生效；版本不一致时自动重抓所有模块（每次发布要同步改 `config.js`、`index.html`、`sw.js`，`npm test` 会检查）。
- **AI（可选）**：议价建议、客户建议、送货路线。和家庭学堂 / 牧羊人同一套：**自带 key、浏览器直连、没有服务器**；在「更多 → AI 助手」填，只存本机浏览器，不同步给合伙人；同域名下爱家小助手里填过的 key 自动沿用。支持 Gemini / OpenAI / Claude / Groq / 自定义。
- **客户画像**：规则打分，给出是否建议明年继续、建议定金和赊账上限、保障措施；手机号默认遮挡；AI 只收脱敏数字。
- **送货路线**：把顺路的几家合成一趟，建议顺序、估算省多少里程和车费，可手动调整，成本自动分摊。AI 建议可选。
- **报表**：利润 / 成本 / 年趋势 / 月度 / 热销 / 种子公司 × 品种盈亏 / 客户；按年、季节、品种、种子公司、客户、收款状态、日期筛选；导出 CSV、打印。
- **打印**：销售单（客户联 + 存根联，不含私下价）、客户对账单、种子公司对账单。都是自己的单据，不是税务发票。
- **审计**：每次新增 / 修改 / 删除都留痕（云端由数据库触发器写，客户端绕不过去）；只做软删除。
- **语言 / 币种**：简体、繁體、English；简繁默认 ¥ + 斤，English 默认美元（汇率自己设）；单位可选 斤 / 公斤 / 磅。
  录入始终按 ¥ 和斤，显示、报表、导出、打印才换算，避免来回换算的误差。

## 本地运行（本机模式，不需要任何账号）
```
cd seed-ledger
python -m http.server 8765      # 然后打开 http://localhost:8765
npm test                        # 账务逻辑的单元测试（Node 18+）
```
`config.js` 里云端没配置时自动进入本机模式：功能完整，数据只在这台设备（IndexedDB），不同步。

## 打开云端同步（多人、多设备）
数据库有**两种部署方式，二选一**（Supabase 免费版同时只能有两个项目），详见 [supabase/README.md](supabase/README.md)：
- **A. 新建独立项目**：执行 `supabase/001_schema.sql`，`config.js` 的 `DB_PREFIX` 保持 `""`。隔离最好。
- **B. 并入 baby-log 现有数据库**：按顺序执行 `supabase/shared-db/sl_001 … sl_004`，`DB_PREFIX` 改成 `"sl_"`，URL 和 key 填 baby-log 项目的。不占项目名额；表和权限独立，但共用项目和配额。

通用步骤：
1. 执行对应的 SQL。Authentication 里打开 Email 登录，URL Configuration 填站点地址。
2. 把 Project URL 和 **anon / publishable key** 填进 `js/config.js`（**绝不要**填 service_role / secret key）。
3. 网站部署后：创建者注册 → 「更多 → 创建经销商账本」；合伙人注册后用邀请码申请，创建者在「成员与邀请」批准。
4. 角色：创建者（管成员）/ 合伙人（可录入）/ 只读。

同步机制：本机优先，录入先存 IndexedDB，联网后逐条上传；上传带上次的时间戳做冲突检测，别人先改过就采用对方版本，自己的那份保存在「更多 → 同步冲突」，不静默覆盖。

## 隐私与安全
- 客户姓名、电话、地址只存在你的 Supabase 项目里（行级权限：只有账本成员能读，只读成员不能写）。
- 发给 AI 的只有脱敏后的数字摘要（金额、等级、扣分原因、镇村名），没有姓名、电话、详细地址；用你自己的 key 直连服务商，不经过任何服务器，key 也不进数据库。
- 导出的 CSV / JSON 含个人信息，请妥善保管。CSV 已防公式注入。
- 前端只放公开的 anon key。

## 目录
```
js/logic/     账务、客户画像、路线（纯函数，有测试）
js/core/      本机数据库、同步、状态、多语言、AI（ai.js 调用层 + advice.js 提示词）、文件读取（file-readers.js）
js/ui/        各页面
supabase/     001_schema.sql（独立项目）· shared-db/sl_*.sql（并入 baby-log）
tests/        node --test
```

## 已知限制
- 云端同步 / 登录 / 成员管理的代码和两套 SQL 已写好（SQL 语法已用 Postgres 解析器检查），但**还没有对着真实的 Supabase 项目跑过**（本机模式和账务逻辑已测）。第一次接上后请按上面步骤走一遍并反馈。
- 历史数据（手抄本）暂无导入工具：先用「补录」方式在销售里选过去的日期录入；以后可以按你们的表格格式加 CSV 导入。
- 路线里程是按「镇离门店多少公里、哪个方向」估算，不是地图导航。
- 汇率手动设置，不自动更新。
- 英文字典覆盖界面主要文字；个别新增文案缺英文时会显示中文原文。
