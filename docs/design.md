# 设计说明（第二版，含钱池、云端同步、合伙人）

## 要解决的问题与成功标准
- **问题**：进货、库存、赊账和催账靠记忆或纸笔，年底对不清账，说不清哪家种子公司、哪个品种、哪个客户赚钱。
- **成功标准**：录一笔销售 10 秒内；随时看到每位客户欠款和每个品种库存；年底一键出报表（可导出、打印）；与种子公司对账一目了然；没有 AI 也能完整使用。

## 业务规则（已确认）
| 项 | 规则 |
|---|---|
| 单据 | 自己的销售单 / 送货单 / 对账单，不是税务发票 |
| 种子公司对账 | 不直接拿钱：打款进「钱池」，进货和手续费从池里扣，退货抵扣回池；期末余额为正 = 结转明年进货款，为负 = 拖欠，要补款 |
| 手续费 | 少见；拆包费，或按退货比例收的退货手续费（例：拿 5000 斤退 4000 斤）。可给种子公司设规则（比例 ≥ X% 按退货金额 Y%）得到建议金额，也可手填 |
| 季节 | 默认早稻 / 一晚 / 二晚；可改名、新增 |
| 语言 / 币种 | 简繁默认 ¥ + 斤；English 默认美元 + 斤，汇率手设；录入固定 ¥ 和斤，显示才换算 |
| 使用者 | 朋友 + 合伙人，云端同步，手机 / 电脑，手机可离线 |
| 留痕 | 所有新增、修改、删除可审计；只软删除；单据只作废不删除 |
| 法律 | 只提供交易记录和风险提示 |
| 隐私 | 客户信息仅账本成员可见；给 AI 的数据脱敏 |
| 历史数据 | 手抄本，待定（暂用补录） |

## 价格模型（四层，各自独立记录）
1. 品种按年的**进货价 / 零售价 / 批发价**（批发价可不设；旧数据的「预售价」就是零售价）。销售单有价格档，按客户的默认档预选。
2. 销售行**单据价**（如 35 元/斤）——记账、打印用。
3. **私下价**（如 33）——只自己看，不上客户联；催账时可一键「按私下价议价」。
4. **催账调整**（每条带原因，可撤销，留痕）：议价（填议价后总额，差额记为调整）、折上折（按当时欠款 × 百分比，金额当场固化）、核销坏账。

## 口径
- 应收 = 货款 − 调整；欠款 = 应收 − 已收。
- 成本 = 数量 × 当年进货加权平均价；送货成本单独计；同一趟送货按数量分摊。
- 利润（应收口径）= 应收 − 成本 − 送货 − 种子公司手续费（手续费按当年进货额摊到该公司的品种）。已收 / 未收另列。
- 库存 = 进货 − 退货 − 已售（作废单不计）；卖超会提示。

## 客户画像（规则，可解释）
扣分项：坏账核销、逾期未结（> 180 天）、往年欠款比例、催账让利幅度、回款慢。输出等级 A / B / C / 新客户，是否建议明年继续，建议定金比例，建议赊账上限（往年已收回的年均额 × 系数），保障措施。AI（可选）只把结果写成口语建议。AI 复用姊妹应用的做法：自带 key、浏览器直连，不走服务器；发出去的是脱敏摘要。

## 同步与权限
- 本机优先（IndexedDB + 上传队列）；`put_record` 带 base 时间戳做冲突检测，冲突时采用服务器版本并保留本机版本。
- 角色（权限从小到大）：viewer 只读 / staff 录入员（能录入，不能管成员）/ partner 合伙人（录入 + 批准申请 + 看邀请码和审计）/ owner 创建者（改角色、移出成员、管邀请码）。只有 owner 能改角色；owner 或 partner 批准加入申请，批准后是 viewer。待批准的人只能看到申请状态。新用户可免邮箱（匿名登录）凭邀请码申请，批准后只能是只读 / 录入员，不能建账本、不能当合伙人 / 创建者。邀请码 7 天有效、过期自动换新、猜码限速。所有写入走服务端函数校验角色。
- 审计日志由触发器写入，无 insert / update / delete 策略，客户端改不了。
